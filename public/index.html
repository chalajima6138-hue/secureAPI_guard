See what is hitting your API, and stop the obvious attacks.

SecureAPI Guard is a gateway that sits in front of your API, inspects each request for SQL injection and cross-site scripting patterns, records security events, and shows them on a private dashboard.

Get started See how it connects

What it does

SQL injection and XSS inspection

Query strings, paths, selected headers and JSON, form and text bodies are decoded and checked against a set of detection rules.

Monitor or block

Start in monitoring mode, which records suspicious requests without interfering. Switch to blocking mode to return 403 before a matching request reaches your backend.

Security event log

Every rule match is stored with its category, severity, rule, request ID and what the gateway actually did. Passwords, authorization headers, cookies and full request bodies are never stored.

Private dashboard

Request volume, allowed versus blocked counts, events by category and recent activity, calculated from your own recorded traffic only.

How you connect an API

  1. Create an account and register your API with its name, environment and backend address.
  2. Receive a gateway address and an API key. The key is shown once. Only a hash is stored.
  3. Route traffic through the gateway. Point your client, reverse proxy or DNS at the gateway address and send the key in an X-Guard-Key header. An API is only protected while its traffic actually flows through the gateway.
  4. Watch the dashboard. The connection shows as active after the first request is seen. Review events, then enable blocking when you trust the rules against your traffic.
curl https://your-guard-host/gateway/<api-id>/v1/products?limit=10 \
  -H "X-Guard-Key: sag_..."

Requests flow: your application, then the SecureAPI Guard gateway, then your backend API.

Current limitations

Detection is rule-based and heuristic. It will miss some attacks and will sometimes flag harmless input. It complements, and does not replace, parameterized queries, output encoding, authentication, authorization and input validation in your own code.

  • Only SQL injection and XSS patterns are checked. Other attack classes are not detected.
  • Multipart uploads and binary bodies are forwarded but not inspected.
  • Responses from your backend are not inspected.
  • The service currently runs as a single instance with a local database and is intended for controlled pilots.
  • Requests that bypass the gateway are neither seen nor protected.
